# Switch family: reference and native evidence

The shared controlled switch uses a recipe generated from the published DSH primitive. It supports pointer and keyboard activation, accessible state and action, disabled behavior, reduced motion, and a focus outline. A parent button draws its focus outline only when it has primary focus, so focusing a nested switch does not outline the parent as well.

Thirty-two comparisons crop the real DSH plugin-manager switch and the Flutter counterpart in on, off and disabled states across desktop and phone densities, English and Chinese, and light and dark themes. All dimensions match; none reaches the unchanged 99.5% non-text threshold, and mean similarity is 87.789%. Sixteen keyboard-focus comparisons capture whole pages; all dimensions match and eight reach 99.5%, with mean 99.540%. These page scores should not be read as isolated switch parity. Eight earlier plugin-manager images remained pixel-identical for both providers. Fonts, classifier and threshold were unchanged.

The exact final tree passed all 13 local preflight checks. Four builds, two hardware-accelerated desktop replays with five assertions each, and five Android scenes passed on a product-equivalent runtime. Android tests checked accessible state and clickability, touch and disabled behavior, and an emulated hardware keyboard's Tab/Space actions and visible focus outline. The final head adds the desktop replay manifest and a brace-only harness lint fix after the runtime build. `receipt.json` records provenance, build hashes, checks and limitations; overall visual parity remains unfinished.
