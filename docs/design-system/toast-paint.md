# Toast paint space

Pinned DSH `687f282e8625c6b8d11ff58211a90524be2e4317`, published ui-primitives0.2.1-rc.2, lays Toast out at `left:50%;top:40px` and applies its centering/entry transform afterwards. Those structural declarations remain locked by the existing complete Toast source contract.

Chromium145's [PixelSnappedContouredBorder](https://chromium.googlesource.com/chromium/src/+/refs/tags/145.0.7632.6/third_party/blink/renderer/core/paint/contoured_border_geometry.cc) snaps the layout border before that transform. Its [PaintNormalBoxShadow](https://chromium.googlesource.com/chromium/src/+/refs/tags/145.0.7632.6/third_party/blink/renderer/core/paint/box_painter_base.cc) derives the shadow and opaque-owner exclusion from the same contour.

The actual published Toast CDP owner-layer command logs demonstrate the distinction. A no-icon desktop DOM box is136.515625×46CSSpx at DPR1, while its local painted contour is137×46 before being translated to x331.7421875. At native DPR2.625 the local painted contour is358×121 internal pixels, with exclusion bounds `[1,1,357,120]`; the literal opaque inset is one internal pixel, not one logical CSS pixel. The existing `dshSnapDensity` conversion implements that unit distinction.

`DshShadowBox.sourcePaintOrigin` and `DshDecoratedBox.sourcePaintOrigin` explicitly provide the source's untransformed layout anchor. With it, the fill, outer shadows and exclusion share the contour snapped in that space. Toast supplies its existing source50%/top anchor. The actual widget size, text layout, centering and fractional entry transform are unchanged. A null origin preserves the prior behavior of every other caller; this is not a global destination-snapping change.

`toast_paint_space_test.dart` reproduces four failures on the preceding implementation across DPR1/2.625, both at rest and during entry. The corrected tests inspect the real canonical fill, outer shadows and exclusion, verify unchanged layout/centering, and cover default callers and an updated paint origin. Path comparisons use its actual float32 coordinate representation without a fitted raster tolerance. Existing opaque-mask, blur, far-shadow, layer-order and ancestor-clip tests remain relevant.

This closes a source paint-contour rule, not full Toast visual acceptance. The completed earlier224-pair cohort remains diagnostic: zero pairs reach fixed non-text99.5%. An integer long-card control shows a separate far-shadow alpha discrepancy even with exact outer/text geometry. A pure-canvas diagnostic using the actual recorded source paths found direct translucent paint and opaque-black+SrcIn produce identical native output, so no ineffective SrcIn production change was made. No sigma, radius, color, token, font, classifier or acceptance threshold was fitted. Final paired/native validation belongs to the integrating owner.
