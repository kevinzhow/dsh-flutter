# Published button-family profiles

DSH remains the acceptance reference. This change follows the design-system-replication workflow: lock the actual consuming dependency and published packages, generate component recipes, keep one button interaction implementation, remove page overrides, ratchet remaining bypasses, and compare the reference's real page with the Flutter implementation. This is one foundation milestone; the design-system migration is **not complete**.

The published `ui-plugin-manager@0.2.1-rc.2` release embeds CSS and its class map as static JSON literals. The implementation verifies archive SHA512, bundle SHA256 and exact decoded snapshots without executing JavaScript. It checks the web-app consumer dependency and compares affected rules with the pinned source. Unknown affected states, conditions, properties and untranslated structural values fail generation. Other rules remain an audit, not translated recipes.

`DshButton` owns primitive/add/icon/info states. `DshSplitButton` gives each half its own superellipse corners, opacity and focus outline, with the source divider inside the menu half. The old page-level outer clip and manually assembled divider are removed. Disabled compound fill naturally changes from RGB159/160/161 to the reference's158/159/160; no alpha or colour tuning is applied. The raw icon action's .5 disabled opacity and explicit outline differ from the small info action's primitive .4 rules and are tested separately. Detected manual metrics decrease997→979. The three local round-icon adaptation callers remain explicit follow-up rather than being falsely assigned this source recipe.
